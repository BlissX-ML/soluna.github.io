1. **放在 `<head>` 中**
    - 浏览器解析 HTML 时遇到 `<script>` 会 **阻塞解析**，直到脚本下载并执行完毕才继续解析后面的内容。
    - 结果：页面渲染延迟，用户可能看到一段时间的“白屏”。
2. **放在 `<body>` 底部**
    - HTML 主体内容先加载和渲染，最后再加载和执行脚本。
    - 结果：用户能更快看到页面内容，体验更好。
    - 👉 常规推荐做法。
3. **`async` 和 `defer` 的区别**
    - **`async`（异步加载，立即执行）**
        - 脚本下载与 HTML 解析 **并行进行**。
        - 下载完成后 **立即执行**，会中断 HTML 解析。
        - 适合 **不依赖 DOM、不依赖其他脚本** 的独立脚本（如广告、统计代码）。
        - **执行顺序不保证**（谁先下载完谁先执行）。
        - `<script async src="..."></script>`
    - **`defer`（延迟执行）**
        - 脚本下载与 HTML 解析 **并行进行**。
        - 等 HTML 解析完成后，再按照顺序依次执行所有 `defer` 脚本。
        - 适合 **依赖 DOM 结构** 的脚本。
        - **执行顺序有保证**（按在文档中的顺序）。
        - `<script defer src="..."></script>`
    - async 和 defer 只对 **外部脚本（src 引入）** 有效，对内联脚本 `<script>...</script>` 无效。
