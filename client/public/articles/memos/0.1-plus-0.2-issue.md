---
titleEn: "Why is 0.1 + 0.2 not equal to 0.3?"
titleCh: "为什么 0.1 + 0.2 !== 0.3"
tags: ["JavaScript"]
---


1. **根本原因：浮点数精度丢失**
    1. **原理**：
        - JavaScript 的所有数字都用 **IEEE754 - 64 位浮点数**存储
        - 像 **0.1 /  0.2 这种小数在二进制中是无限循环小数**
        - 存储时必须**截断 + 取近似值**
        - 两个不精确的数相加 → 误差叠加 → 得到 **0.30000000000000004**
    2. **示例**：
        
        ```jsx
        0.1 + 0.2      // 0.30000000000000004
        0.1.toString(2) // 二进制是无限循环小数
        ```
        
2. **为什么二进制表示不准确？**
    1. **原理**：
        - 0.1 在十进制能写完，但在二进制中是无限循环数
        - 浮点数只能保存有限位，因此一定会产生精度损失
    2. **解释类比**：
        - 就像 1/3 在十进制里是 **0.333333…**，永远写不完
        - 0.1 在二进制里也是写不完，只能凑一个**最接近**的值
3. **解决方法**
    1. **toFixed（四舍五入）**
        - `toFixed(n)` 是 **按小数位数进行四舍五入**，保留 **n 位小数** 的方法
        
        ```jsx
        +(0.1 + 0.2).toFixed(2) // 0.3
        ```
        
    2. **整数放大法（最常用）**
        
        ```jsx
        (0.1 * 100 + 0.2 * 100) / 100 // 0.3
        ```
        
    3. **`Number.EPSILON` 判断相等**
        - `Number.EPSILON === 2.220446049250313e-16`
        - `Number.EPSILON` 表示**浮点数能接受的最小误差**，如果两个数的差值 **小于** 它，就可以认为它们是相等的。
        
        ```jsx
        function equal(a, b) {
          return Math.abs(a - b) < Number.EPSILON;
        }
        equal(0.1 + 0.2, 0.3); // true
        
        ```
        
4. **一句话总结**
    - **0.1 与 0.2 在二进制中无法精确表示，存储后已带误差，两个误差相加导致不等于 0.3。**
