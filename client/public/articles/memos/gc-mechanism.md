1. GC 是做什么的
    - **原理**：自动找出**不再使用、不可达的对象**，释放对应内存。
    - **示例**：
        
        ```jsx
        let obj = { a: 1 };
        obj = null;    // 下次 GC 回收
        ```
        
2. **为什么会出现内存泄漏**
    - **原理**：变量被意外持续引用，导致 GC 认为它仍可达，无法回收。
    - **示例**：
        
        ```jsx
        const arr = [];
        function leak(){ arr.push(new Array(10000)); }
        // arr 永远不清空 → 内存泄漏
        ```
        
3. **现代浏览器唯一主流的 GC 策略：标记清除（Mark-Sweep）**
    - **原理**：
        - 通过**可达性**判断对象是否还被使用。
        - GC 运行时会标记所有**仍然可达**的对象，其余对象视为垃圾并回收。
    - **示例**：
        
        ```jsx
        // 可达链：window → obj
        const obj = { x: 1 };
        // obj = null 后，它不再可达 → 可回收
        ```
        
4. **历史遗留：引用计数（仅旧 IE 使用）**
    - 原理：每个对象维护引用次数，归零即回收；但会陷入循环引用问题。
    - 示例：
        
        ```jsx
        // 循环引用（旧 IE 无法回收）
        const a = {};
        const b = {};
        a.b = b;
        b.a = a;
        ```
        
5. 一句话总结
    - 原理：现代 GC 的核心是**可达性分析**，只要对象“不再可达”，就会被标记清除。

        ```jsx
        // 只要对象不再能从根对象（如 window）访问到，就会被 GC 清理
        ```
