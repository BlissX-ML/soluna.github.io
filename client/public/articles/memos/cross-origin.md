1. **定义**
    - **跨域**：由 **浏览器的同源策略**（协议、域名 /  IP、端口必须相同）带来的限制。
    - **本质**：当前页面和请求目标**三者有任意一项不同**，浏览器会禁止前端**读取**响应内容（可以请求）
2. **常见解决方案**
    - **JSONP（旧方案）**
        - 利用 `<script>` 标签不受同源限制，请求返回 `js` 脚本并执行回调函数
        - **优点**：简单易用，兼容老浏览器
        - **缺点**：仅支持 GET，**不安全**，需要后端配合
        - **步骤**：创建 script 标签 → 设置 src 为接口地址 → 添加 callback 参数 → 定义同名函数接收数据
    - **CORS（主流方案）**
        - 通过 **HTTP 响应头** **`Access-Control-Allow-Origin`** 告诉浏览器允许跨域
        - **优点**：支持多种请求方式（GET/POST/PUT…），简单直接
        - **缺点**：需要**后端配置**
    - **Proxy 代理 + Nginx（推荐）**
        - 浏览器限制是 **前端跨域**，但 **服务器与服务器通信没有跨域问题**
        - **代理服务器**（如 Nginx）接收请求 → 转发给目标服务器 → 返回数据
        - **优点**：开发环境可用 proxy，生产环境用 Nginx，灵活高效
    - **window.postMessage()（H5 特性）**
        - 用于不同窗口/iframe 之间安全通信
        - 适用于 **跨文档消息传递**，而不是常规接口请求
3. **跨域的特点**：
    - 跨域是浏览器为安全设置的限制，本身是好的，但会给前端开发带来不便
    - 需要通过 CORS、代理等方式解决。
