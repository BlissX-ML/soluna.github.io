1. **对称加密**
    - **特点**：加密和解密使用**同一把密钥**。
    - **优点**：效率高，算法简单，系统开销小，适合**加密大量数据**。
    - **缺点**：**安全性差，密钥分发难**（密钥一旦泄露，数据容易被破解）。
    - **流程**：
        - 发送方：用共享密钥加密消息 → 发出去。
        - 接收方：用相同密钥解密。
    - **常见算法**：
        - **DES**：分组加密，64位分组，密钥较短，现在已不够安全。
        - **3DES**：对每个数据块进行三次 DES，加密强度更高但效率低。
        - **AES**：高级加密标准，目前广泛使用，安全性高。(Advanced Encryption Standard)

2. **非对称加密**
    - **特点**：使用**一对公钥和私钥**。
        - 公钥：公开
        - 私钥：保密
        - 公钥加密 → 只有私钥能解密；私钥加密 → 只有公钥能解密。
    - **优点**：**安全性高**，支持签名和认证。
    - **缺点**：运算**效率低**，速度比对称加密慢很多。
    - **流程（接收人的密码）**：
        - 发送方：用 **接收方的公钥** 加密消息。
        - 接收方：用自己的 **私钥** 解密。
    - **常见算法**：
        - **RSA**
            - 基于大素数分解难题。
            - 应用：常用于加密对称加密所需的密钥（**混合加密**）。
            - **RSA 更常用，既能加密/解密，也能签名/验签。**
        - **DSA / DSS**
            - **DSA：**数字签名算法，**只能用于签名/验签**，不支持加解密。
            - **DSS：**数字签名标准，**可用于签名，也可用于加解密**。
            - DSA/DSS 更多用在需要**签名验证**的场景。

3. **混合加密（实际应用中常用）**
    - **原理**：
        - 使用 **非对称加密（RSA）** 来加密 **对称密钥（AES）** 并传输。
        - 数据本身的加密和解密则使用 **对称加密（AES）** 来完成。
    - **流程**：
        - 发送方：生成一个临时的对称密钥（AES）。
        - 发送方：用 **接收方的公钥 (RSA)** 加密这个对称密钥，传输过去。
        - 接收方：用 **私钥** 解密得到对称密钥。
        - 双方用这个对称密钥（AES）来加密/解密消息内容。
    - 好处：既有对称加密的高效率，又有非对称加密的高安全性。
