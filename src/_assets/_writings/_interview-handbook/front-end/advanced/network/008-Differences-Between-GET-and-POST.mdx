1. **功能差异**
    - GET：用于**获取**数据（查询，只读）。
    - POST：用于**提交**数据（新增、修改、删除）。

2. **参数传递方式**
    - GET：参数拼接在 **URL** 中。
    - POST：参数放在**请求体 (Request Body)**。

3. **参数大小**
    - GET：长度**有**限制（受 URL 长度限制，不同浏览器/服务器约 2~8KB）。
    - POST：理论上**无**限制。

4. **安全性**
    - GET：参数暴露在 URL 中，不适合传递敏感信息。
    - POST：参数在请求体，**相对更安全**，但本质上仍需 HTTPS 才真正安全。

5. **浏览器回退/刷新表现**
    - GET：回退/刷新是**无害**的（只会重新请求数据）。
    - POST：回退/刷新可能**导致表单重复提交**。

6. **缓存与历史记录**
    - GET：浏览器会**缓存响应**，参数**会保存**在历史记录中。
    - POST：默认不会缓存，参数也不会保存到历史记录。



#### 对比总结表

- 功能 - 参数传输 - 大小限制 - 安全性 - 回退/刷新 - 缓存 - 历史记录
- GET 用于获取数据，参数放 URL，可被缓存和记录；POST 用于提交数据，参数放请求体，不会被缓存，但是否安全取决于是否使用 HTTPS。

| 对比点 | GET | POST |
| --- | --- | --- |
| **语义** | 获取数据（只读） | 修改数据（写入/提交） |
| **参数位置** | URL | Request Body |
| **大小限制** | 有限制（取决于浏览器） | 理论无限制 |
| **安全性** | 低（参数明文出现在URL） | 相对高（需配合 HTTPS 才安全） |
| **回退/刷新** | 无害 | 可能导致重复提交 |
| **缓存** | 默认可缓存 | 默认不缓存 |
| **历史记录** | 参数会被记录 | 参数不会记录 |
